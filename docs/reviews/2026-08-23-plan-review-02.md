## Important

### I1 — M2 still claims it cannot do high-risk, after putting the reader in M2

§3 cut-line table: M2 "You do not have: Physical hardware, **high-risk
readability**." Prose under it: "M2 supports **low and medium risk only**,
because v1.2 made a full-fidelity reader a prerequisite."

§4.3 and §13: AIR-18 lands in M2, either reader qualifies, Q1 is closed,
"nothing in this plan is now conditional on Q1."

Those cannot both be true. The cut-line table is the leftover of the
unanswered-Q1 draft. An orchestrator using §3 as the MVP definition will treat
high-risk as out of scope at the milestone that now owns the reader.

`DESIGN.md` §9 is part of the same miss: high-risk LCD copy is still `SEE
DASHBOARD`. At M2 the dashboard is not built (AIR-13 is M4). The device would
point the operator at a surface that does not exist.

### I2 — §4.1 still gives `airgap watch` the `ui` token

PLAN.md line 109: "over `ui` scope."

§5, AIR-18, `spec/03` v1.1, and DESIGN N-T8 all say `ui_ro`. AIR-18's `reads`
list includes this file. The intro table is the line a session sees first; it
is the credential review 01 I3 said must not be in a long-running CLI.

Same-file P1, after I3 was accepted.

### I3 — no ticket mints the short code AIR-18 and T1 depend on

DESIGN §4.2 / §9 / §13: high-risk LCD shows a **per-arm nonce**, never a
truncatable identifier; a full-fidelity reader carries the real action.

AIR-18 **consumes** that nonce ("short code shown matches the armed request's
per-arm nonce"). Nothing **produces** it. AIR-9 (who would write the LCD at
arm) does not mention risk class, LCD copy, or a nonce. AIR-14's scenarios do
not include DESIGN §13's T1 test. PLAN §5 justifies the AIR-14 → AIR-18 edge
as "the reader is how high-risk scenarios are asserted"; the ticket body never
asserts them.

Q1 moved AIR-18 onto the MVP path. The control that made that necessary is
still only prose in `DESIGN.md`.

### I4 — AIR-11 still forbids the `vocab` import P1 now requires

AIR-1, AIR-2, AGENTS.md §5, and PLAN P1: `policy.py` may import `airgap.vocab`
and nothing else.

AIR-11 last acceptance criterion: "No imports from elsewhere in `airgap`."

AIR-11 implements `Verdict` and the resolution table. Inline enums are the
drift AIR-16 exists to stop. Importing `vocab` fails this ticket's own AC.
Review 01 I2 was applied to the codec and not the other pure-core module.

### I5 — AIR-9 keys Origin rejection on **routes**, `spec/03` keys it on **token scopes**

`GET /pending` is both a `ui` route and a `ui_ro` route.

`spec/03`: a `ui` token allowlists `Origin` (the dashboard is a browser); a
`ui_ro` token rejects it.

AIR-9: "`/request_approval` and **`ui_ro` routes** reject any request carrying
an `Origin` header."

Implemented as written, `GET /pending` rejects `Origin` and the dashboard
cannot read the queue — the v1.1 blanket-Origin break (design review 02 I4)
replayed on the shared read path. Implemented against `spec/03`, the ticket AC
is wrong. §10 again.

### I6 — AIR-17's "reproduced" list drops a `spec/02` obligation

`spec/02` `test_interlock.py`:

> an auto-approved request never closes the relay, however policy is configured

AIR-17 says it is scored on that list, then omits this bullet. Consent-channel
"no relay command" is not the same test: auto-approve is a verdict,
`relay_gated` is a policy bit, and D12 needs both. A session following the
ticket's reproduction will not write the D12 case.

### I7 — `spec/01`'s `err` vocabulary omits `not_closed`

Same file:

- relay table: `{"ok":false,"err":"not_closed"}`
- closed list: `err` is one of `unknown_cmd`, `bad_field`, `out_of_range`,
  `not_armed`, `busy`

AIR-16's job is both-directions set equality on ack error codes. Either wave 2
stops on this (correct, and no agent can edit `spec/01`) or the parser only
reads tables and the prose stays stale. Frozen-contract defect, same class as
C1, smaller blast radius.
